# 01. Время жизни объекта: Rule of Five, Rule of Zero, copy-and-swap

Читать 20 минут, писать код 40 минут.

## Что спросят

**Назови пять специальных методов.** Деструктор, копирующий конструктор, копирующее
присваивание, перемещающий конструктор, перемещающее присваивание.

**Правило.** Объявил один — объявляй все пять (Rule of Five), либо не объявляй ни одного
(Rule of Zero). Полумеры дают тихое копирование.

**Главная ловушка.** Объявленный деструктор — даже пустой — **подавляет неявные
перемещающие операции**. Класс остаётся копируемым, и `std::move` молча копирует.

    класс с vector внутри, перемещение объекта целиком:
      без объявлений         -> копий 0, перемещений 0
      добавлен пустой ~T(){} -> копий 3, перемещений 0

`std::is_move_constructible` это скрывает (отвечает «да», потому что rvalue связывается
с `const&`). Честный признак — `std::is_nothrow_move_constructible`.

**Что обязано быть в копирующем присваивании.** Два требования:
освободить старый ресурс и выжить при самоприсваивании. Проверка `this == &other`
закрывает только второе.

**Copy-and-swap** закрывает оба разом:

```cpp
void swap(T& o) noexcept { std::swap(a_, o.a_); std::swap(b_, o.b_); }
T& operator=(const T& o) { T(o).swap(*this); return *this; }
T& operator=(T&& o) noexcept { T(std::move(o)).swap(*this); return *this; }
```

По шагам для `a = b`:

1. Создаётся временный объект — копия `b`.
2. `swap` обменивает указатели: у `a` данные копии, у временного — старый буфер `a`.
3. Конец выражения: деструктор временного удаляет **старый буфер `a`**.

При `a = a` работает потому, что копия сделана **до** любых изменений: умирает копия,
а не то, чем ты продолжаешь пользоваться.

**Почему `swap` обязан быть `noexcept`.** Это точка фиксации. Бросок посередине обмена
оставит поля перемешанными (`size_` от одного объекта, `data_` от другого), и откатить
нечем.

**Где copy-and-swap применять нельзя.** В конструкторе: `T(other)` внутри копирующего
конструктора вызывает сам себя (замерено: 52340 рекурсивных входов, stack-overflow),
а `swap` обменивается с неинициализированными полями.

**Если исключение при копировании.** `swap` не вызовется, `a` не изменится вообще —
это strong-гарантия. Но конструктор обязан быть безопасным сам: если он захватил сырой
ресурс и бросил, объект не создан, деструктор не вызовется, и убирать должен `catch (...)`
внутри конструктора.

| Факт | Значение |

## Задание на вечер

Файл `lifetime_task.cpp`, собирать так:

```bash
g++ -std=c++17 -g -Wall -Wextra -Wshadow -fsanitize=address,undefined lifetime_task.cpp -o t && ./t
```

1. Напиши класс `Buffer`, владеющий сырым `int*` и `size_t`, со **всеми пятью** методами
   вручную. Копирующее присваивание — через copy-and-swap, перемещающее — через
   move-and-swap.
2. Добавь `swap` с `noexcept`.
3. В `main` проверь четыре сценария и напечатай результат:
   `a = b` (старый буфер освобождён), `a = a`, `a = std::move(b)`, `a = std::move(a)`.
4. Добавь счётчики аллокаций через перегрузку `operator new[]`/`operator delete[]`
   и покажи: копия — одна аллокация, перемещение — ноль.
5. Вторым классом напиши `BufferZero` с `std::vector<int>` внутри и **без единого**
   объявленного специального метода. Убедись, что все четыре сценария работают так же.
6. Допиши в `BufferZero` пустой деструктор `~BufferZero() {}` и покажи, что перемещение
   превратилось в копирование.
