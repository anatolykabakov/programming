# 03. Умные указатели

Читать 15 минут, писать код 45 минут.

## Что спросят

| Вопрос | Ответ |
|---|---|
| `sizeof` | `unique_ptr` — 8, `shared_ptr` — 16 (указатель на объект + на control block) |
| Аллокации | `shared_ptr<T>(new T)` — 2, `make_shared<T>()` — 1 |
| Минус `make_shared` | объект и блок в одной аллокации: память под объект держится живым `weak_ptr` даже после смерти объекта |
| Цикл ссылок | две стороны держат друг друга `shared_ptr` → счётчики не дойдут до нуля; одну сторону делают `weak_ptr` |
| `weak_ptr::lock()` | CAS-цикл, а не «проверил и увеличил»: между проверкой и инкрементом объект может умереть |
| Два счётчика | strong = 0 → разрушить объект; weak = 0 → освободить память блока |

**Потокобезопасность.** Атомарен **только счётчик**:

- два потока копируют один `shared_ptr` — **гонки нет**;
- один делает `reset()`, другой копирует — гонка;
- запись в `p->field` из двух потоков — гонка, указатель объект не защищает.

**`memory_order` в счётчике.** Инкремент — `relaxed` (ничего не публикуем, просто
«нас стало больше»). Декремент — `acq_rel`: release, чтобы записи уходящего увидел тот,
кто вызовет деструктор; acquire, чтобы последний уходящий увидел записи остальных.

**Решение принимается по возвращённому значению:**

```cpp
if (cb_->counter.fetch_sub(1, std::memory_order_acq_rel) == 1) { delete ptr_; delete cb_; }
```

Вариант `--counter; if (counter == 0)` — это две операции вместо одной, два потока
увидят ноль и оба удалят. Замерено: `AddressSanitizer: attempting double-free`.

**`make_shared` и исключения.** Историческая ловушка:
`f(shared_ptr<Foo>(new Foo()), bar())` — до C++17 порядок вычисления аргументов был
не определён, и при броске `bar()` объект утекал. С C++17 ловушка закрыта языком.
Сегодня главный аргумент за `make_shared` — одна аллокация вместо двух.

## Задание на вечер: написать оба указателя с нуля

Не патчить старый файл, а написать заново — на интервью просят именно это.
Файлы `my_unique_ptr.cpp` и `my_shared_ptr.cpp`, каждый со своим `main`.

Собирать так:

```bash
g++ -std=c++17 -g -Wall -Wextra -Wshadow -fsanitize=address,undefined my_unique_ptr.cpp -o t && ./t
```

### `MyUniquePtr<T>` — 20 минут

Чеклист, по которому интервьюер ставит галочки:

- [ ] конструктор по умолчанию (пустой) и `explicit` от `T*`
- [ ] копирование **удалено**: `= delete` для конструктора и оператора
- [ ] перемещающий конструктор, `noexcept`, обнуляет источник
- [ ] перемещающее присваивание, `noexcept`, безопасно при самоперемещении
- [ ] деструктор
- [ ] `get()`, `operator*`, `operator->`, `explicit operator bool` — все `const`
- [ ] `release()` — отдать владение, не удаляя
- [ ] `reset(T* p = nullptr)` — удалить старое, взять новое
- [ ] `swap(MyUniquePtr&) noexcept`

Проверить в `main`: перемещение (источник пуст), самоперемещение (объект цел),
`release` (объект не удалён, указатель отдан), `reset` (старое удалено),
`MyUniquePtr<int> p(new int[10])` — объяснить в комментарии, почему это дефект
и как настоящий `unique_ptr` его решает.

Сказать вслух, но **не реализовывать**: настоящий `unique_ptr` имеет второй
шаблонный параметр-делетер, и делетер без состояния не увеличивает `sizeof`,
а указатель на функцию увеличивает с 8 до 16.

### `MySharedPtr<T>` — 40 минут

- [ ] `ControlBlock` со `std::atomic<long> strong` (и `weak`, если делаешь `MyWeakPtr`)
- [ ] `explicit` конструктор от `T*`; при исключении на выделении блока — `delete p`
- [ ] копирующий конструктор от `const MySharedPtr&`, **один** инкремент
- [ ] копирующее присваивание через copy-and-swap: ни `release_`, ни `++counter` внутри
- [ ] перемещающий конструктор и присваивание, `noexcept`, счётчик **не трогают**
- [ ] деструктор через `release_()` с `fetch_sub(1, acq_rel) == 1`
- [ ] `release_()` начинается с `if (!cb_) return;` — после перемещения блока нет
- [ ] `get()`, `operator*`, `operator->`, `use_count() const`, `operator bool`, `swap`, `reset`

Проверить в `main`, печатая `use_count()` на каждом шаге: копия из неконстантного и
из **константного** объекта, `a = b` двух разных объектов, `a = a`, `std::move`,
самоперемещение. ASan должен молчать.

Если останется время — `MyWeakPtr<T>` с `lock()` через CAS-цикл и демонстрация
разорванного цикла ссылок на двух узлах.
