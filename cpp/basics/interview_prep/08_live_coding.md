# 08. Live coding

Это единственный блок, где оценивают не знание, а привычки. Читать 5 минут,
решать задачи 60 минут.

## Ритуал — порядок жёсткий

1. **Уточнить условие.** Размер входа, диапазон значений, дубликаты, пустой вход,
   можно ли портить вход.
2. **Проговорить 2–3 примера вслух**, включая крайние: пустой, один элемент,
   всё одинаковое.
3. **Назвать сложность по времени и памяти — до кода.** Если решение заведомо
   квадратичное, сказать это и объяснить, чем улучшишь.
4. **Писать компилируемый C++**, не псевдокод, без автодополнения.
5. **Прогнать вручную** на своём же примере, вслух.
6. **Самому назвать edge cases** и где решение сломается.

За четырнадцать разобранных задач сложность до кода не была названа **ни разу**. Это
самое заметное на интервью и стоит дороже любой опечатки.

## Твои шесть ошибок и что из них следует

| Ошибка | Почему прошла мимо примеров |
|---|---|
| `j = i + i` вместо `i + 1` в 3Sum | верно ровно при `i = 1`, а пример из условия решается именно там |
| `push` закрывающих скобок вместе с открывающими | ломает вложенность, но не плоские примеры |
| `return valid` при затенённой переменной | ловится флагом `-Wshadow`, которого нет в `-Wall -Wextra` |
| `i < size() - 2` на коротком входе | беззнаковое переполнение и SEGV, вне ограничений задачи |
| нет раннего выхода в Contains Duplicate | асимптотика та же, а на 100000 элементов в 100 раз медленнее |
| `unordered_set<char>` вместо массива | в 25 раз медленнее, тесты при этом зелёные |

**Вывод:** прогонять на входе, которого нет в условии, и обязательно на таком, где
ответ отрицательный или пустой. Пустой ответ — самый чувствительный тест.

## Бинарный поиск: две схемы, не смешивать

| Интервал | Условие | Сдвиги | Начальное `r` |
|---|---|---|---|
| закрытый `[l, r]` | `l <= r` | `l = m + 1`, `r = m - 1` | `size() - 1` |
| полуоткрытый `[l, r)` | `l < r` | `l = m + 1`, `r = m` | `size()` |

В закрытой схеме при `l == r` остаётся один непроверенный элемент — поэтому `l <= r`;
`m` уже проверен и обязан выйти из интервала — поэтому `r = m - 1`. Оставить `r = m`
в закрытой схеме — вечный цикл.

Всегда `m = l + (r - l) / 2`: `(l + r) / 2` переполняет `int` при поиске **по ответу**,
где границы это значения, а не индексы.

## Задание на вечер — три задачи

Сборка каждой:

```bash
g++ -std=c++17 -Wall -Wextra -Wshadow -fsanitize=address,undefined task.cpp -o t && ./t
```

**704. Binary Search** — отсортированный массив различных чисел, вернуть индекс `target`
или −1. Напиши **обе** схемы интервала, обе должны проходить одни и те же тесты.

**35. Search Insert Position** — то же, но при отсутствии вернуть позицию для вставки.
Объясни письменно, почему ответ это `l` после выхода из цикла. Вторым решением
назови `std::lower_bound`.

**21. Merge Two Sorted Lists** — слить два отсортированных списка. **Не создавать новые
узлы**, только переставлять указатели. Используй dummy head. Остаток непустого списка
прицепить одним присваиванием, а не циклом.

К каждой задаче в комментарии наверху файла напиши **до кода**: идею одной строкой,
сложность по времени, сложность по памяти. Тесты пиши сам, включая пустой вход и
один элемент.
